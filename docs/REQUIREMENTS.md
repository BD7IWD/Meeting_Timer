## 二、我拟定的默认项（不同意就在开工前说）

### 2.1 通信
- **UDP 发现端口 `47820`**：客户端广播 `DISCOVER`，主控单播 `HERE` 应答（含主控 IP + TCP 端口）
- **TCP 控制端口 `47821`**：主控 = Server，客户端 = Client；长连接
- **报文格式**：`4 字节魔数(0x4D544D52 "MTMR") + 4 字节长度(大端) + JSON payload + 4 字节 CRC32`
  - 按字节喂入**状态机**解析，不假设"一次 recv 就是一整帧"
  - 粘包 / 分包 / 半包 全部容错
- **心跳**：客户端每 2 秒发 `HEARTBEAT`；主控 6 秒收不到即判定离线，从列表移除
- **断线重连**：客户端 2 秒重试，重连成功后主控**自动补发当前剩余时间**（断网不丢倒计时）

### 2.2 报文类型
| 类型 | 方向 | 说明 |
|---|---|---|
| `DISCOVER` / `HERE` | C→M 广播 / M→C 单播 | 发现握手 |
| `REGISTER` | C→M | 上报主机名、IP、MAC、版本 |
| `START` | M→C | 下发总秒数 + 绝对目标时间戳(epoch ms) |
| `ADD_TIME` | M→C | 加时秒数 → 客户端重算目标时间戳 |
| `STOP` / `RESET` | M→C | 停止 / 重置回无界面状态 |
| `HEARTBEAT` | C→M | 携带当前剩余秒数、状态(idle/running/finished) |
| `ACK` | C→M | 收到关键指令的确认 |

### 2.3 计时精度（关键）
- **不使用"每秒累减计数器"**，而是记录**绝对目标时间戳**，用 `剩余 = 目标 - 当前系统时间` 计算
- 理由：`QTimer` 累加在系统休眠、CPU 满载、调试断点时会漂移，会议提醒漂几分钟就失去意义
- 弹窗判据：**"严格跨过"节点才弹**。设 10 分钟时起始瞬间不弹；设置 8 分钟时 10 分钟节点不弹（因为压根没跨过）

### 2.4 加时与节点标记
- 每个节点 `[10, 5, 3, 1] 分钟` 各自带"已弹过"标记
- **加时后，若剩余时间重新大于某节点阈值，该节点标记自动重置** → 会再次提醒
- 理由：加时 = 会议顺延，"还剩 10 分钟"再提醒一次是合理的
- **【最终决定】** 按默认执行（加时后节点重新可弹）。这是个一行开关，
  在 `common/const.py` 里：`ADD_TIME_RESETS_NODE_FLAG = True` 会重复提醒，
  改成 `False` 则本轮内已弹过的节点不再弹。

### 2.5 横幅显示（关键细节）
- 窗口标志：`Qt.Tool | Qt.FramelessWindowHint | Qt.WindowStaysOnTopHint`
- **`WA_ShowWithoutActivating`** → 弹出时不抢焦点，全屏放映的 PPT 不会被打断
- **抢占式置顶**：弹出瞬间走 Win32 `SetWindowPos(HWND_TOPMOST)` 并短暂提到最前，把焦点还给原窗口 —— 解决"PPT 放映时置顶窗口被盖住"的经典坑
- 半透明：`setWindowOpacity(0.85)`；横幅内部再套一层深色底（`rgba(20,20,20,220)`）保证文字对比度
- 节点横幅 10 秒后自动淡出消失；到点横幅常驻直到点击/`ESC`

### 2.6 客户端静默运行
- 无主窗口、无任务栏图标，只有**系统托盘图标**
- 图标用代码画（`QPainter` 生成），**不依赖外部 png 文件**，避免打包丢资源
- **单实例锁**：用 `QLocalServer` 命名管道防止重复启动（否则会开两个进程抢托盘）
- **日志**：写入 `%LOCALAPPDATA%\MeetingTimer\client.log`，按天轮转保留 7 天（无界面程序唯一的排障手段）

### 2.7 主控端界面
- 上方：剩余时间**大字显示**（`30:00`）
- 中间：时间设置（分钟，支持 1~180）+ `开始` / `加5分` / `加10分` / `停止` / `重置` 按钮
- 下方：**在线客户端列表**（主机名 / IP / 状态 / 剩余），实时刷新
- 状态栏：本机主控 IP、端口、监听状态

### 2.8 不做的事（明确排除）
- ❌ 不做密码 / 房间码验证（内网可信环境；需要的话再加）
- ❌ 不做客户端多选、分组、不同客户端不同时间
- ❌ 不做开机自启
- ❌ 不做跨网段 / 公网穿透

## 三、防火墙提醒（重要）

首次运行 exe 时 **Windows 会弹"是否允许通过防火墙"** —— 客户端与主控端都必须点 **"允许访问"**，
否则 UDP 广播和 TCP 连接都会被静默拦截，表现为"客户端一直显示未连接"。
若误点了"取消"，需到 `控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙` 手动放行。

## 五、验收标准

1. 主控端点"开始 30 分钟" → 同机客户端**立即**进入倒计时（无界面无打扰）
2. 剩余跨过 10/5/3/1 分钟 → 客户端**横跨全屏宽、居中、半透明**横幅弹出对应文案，**10 秒自动消失**
3. 横幅弹出**期间不抢焦点**——正在全屏放映的 PPT **不被打断**
4. 剩余归零 → 常驻横幅 `时间到`，点文字或按 `ESC` 关闭
5. 运行中**拔网线/断 Wi-Fi 10 秒再插回** → 客户端自动重连，剩余时间**不倒退、不归零**，继续正常提醒
6. 主控端按"加 10 分" → 客户端剩余时间**同步 +10 分钟**
7. 托盘图标可查看状态、立即重连、正常退出
8. 打包出的 exe 在**未装 Python** 的机器上双击可运行

### 开发过程中真实踩到并修掉的坑（都写进代码注释了）

| 现象 | 根因 | 修法 |
|---|---|---|
| 倒计时一开就判超时 | `pyqtSignal(int)` 映射到 C++ **32 位** int，epoch 毫秒（1.79×10¹²）高 32 位被无声砍掉，目标时间戳变成 1970 年 | 信号与槽签名统一改成 `qint64` |
| 主控端一启动就崩 | `pyqtSignal(int)` 连 `@pyqtSlot("qint64")` 签名不兼容，直接抛异常 | 界面侧信号也改成 `qint64` |
| 横幅**完全看不见** | `WA_TranslucentBackground` 与 `setWindowOpacity` 冲突（Windows 分层窗口路径），透明度卡在 0 | 半透明与淡入淡出改为 `paintEvent` 自绘 alpha |
| 淡入淡出不动 | Qt 动画驱动（QUnifiedTimer）在本机实测不推进，动画"跑完"值却不变 | 改用 `QTimer` 定步长手动推进 |
| 置顶静默失效 | ctypes 未声明 `argtypes`，`HWND_TOPMOST = -1` 被当成 32 位截断成非法句柄 | 显式声明 `SetWindowPos` 的 `argtypes`/`restype` |
| 测试退出时段错误 | 局部 `QApplication` 被 GC 掉后再析构其它 QObject，无 QApplication 的裸析构 | 保持全局引用 |
| 首次弹出慢约 1 秒 | 首次绘制大号中文字体，CJK 字体初次加载阻塞事件循环 | 属正常现象，已写入 README 常见问题 |

**为什么"去掉背景"不是只删几行**：横幅是一条"全宽 × 25% 屏高"的窗口。
有底色时用户知道哪块能点；底色一去掉，屏幕上那一条就变成**完全看不见、
却仍然会吃掉鼠标点击**的区域（尤其在屏幕正中）。所以必须同步用 `setMask`
把可点击范围收缩到文字本身——这属于"需求隐含的必做项"，不做的话用户会以为鼠标坏了。

### v1.3 —— 描边压缩到原来的 1/3

**需求**：文字的描边太宽了，压缩到目前描边宽度的 1/3。

**改动**：

| 改动点 | 原值 | 新值 |
|---|---|---|
| `BANNER_TEXT_OUTLINE_RATIO` | `0.062` | **`0.0207`**（≈ 0.062 / 3） |
| 新增 `BANNER_TEXT_OUTLINE_MIN_PX` | 代码里硬编码 `2.0` | **`1.0`** |

⚠️ **第二条是必须一起改的**：原来描边宽度算的是 `max(2.0, 字号 × 比例)`。
在 90px 字号下 `90 × 0.062 = 5.58`，若只把比例改成 1/3，`90 × 0.0207 = 1.86`
会被那个 `2.0` 的下限**顶回去**，实际只减到 0.36 倍（不是 1/3）。
所以把下限一起降到 1.0px（只在小字号时兜底），比例才真正生效。
这也是个通用教训：**加了下限/上限的算式，改比例时一定要检查边界会不会盖过比例。**

**验证结果**（4 种横幅各 15 项全过）：

```

  改动前同字号下是 5.58 px -> 现在为 0.33 倍（目标 1/3 ≈ 0.33）   [PASS]
```

### v2.2 —— 修界面排版：议程页底部按钮压到边框

**需求**（用户反馈 + 截图）：议程页最下面那排按钮（＋添加议程 / 编辑 / 删除 / ↑ / ↓ / +10分钟顺延 / 立即进入下一项）压在边框上，↑ ↓ 还被裁掉一截。

**真因**（不是简单的"边距不够"）：

切到议程页时整页被压扁到 285px，而内容需要约 470px —— 最下面那排按钮被挤出可见区域，
看起来就是"压在边框上 / 被裁掉"。

**改动**（`master/ui_master.py`）：

| 改动 | 说明 |
|---|---|
| 显式给 `tabs` 设最小高度 = 两页里更高的那个 + 标签栏高度 + 14 | 根治"压扁" |
| 两个标签页内边距 `(2, 8, 2, 2)` → `(6, 10, 6, 10)` | 下边距原来只有 2px |
| `↑`/`↓` 由 `setMaximumWidth(40)` 改为 `setFixedWidth(38)` + `setMinimumHeight(34)` | 原来没设高度，比旁边按钮矮一截 |
| `编辑`/`删除` 补 `setMinimumHeight(34)` | 按钮行等高 |
| 议程表格最小高度 170 → 150；窗口 980×820 → 1000×940 | 给底部按钮行让出空间 |

**新增回归脚本 `tests/layout_check.py`（13 项）**：
这类问题单元测试测不出来（测试从不显示窗口，几何全是 0），所以单独做离屏排版检查：
用 `WA_DontShowOnScreen` 让 Qt 正常计算布局但不上屏，然后逐项断言
"每个按钮完整落在页面内""按钮等高""底部留白 ≥ 6px""表格与按钮行不重叠""反复切页后仍然正确"。
实测修复后：7 个按钮全部 `y=219..253`、高 34、**距页面底边 31px**。

> 量坐标时踩了个坑：这些按钮的 parent 就是页面本身，`mapTo(page, b.geometry().topLeft())`
> 会重复叠加一次父偏移，y 直接翻倍，差点把好布局判成 FAIL。正确写法是 `mapTo(page, QPoint(0, 0))`。

# 多主控版需求确认书（v3.0）

> 本文件上半部分是单主控版的历史记录（原样保留），本节起是多主控版。

## 一、需求（用户原话）

> 这个版本保留，生成另外一个版本，新版本要求如下：
> 1：允许局域网内多主控对多客户端一对一控制
> 2：客户端可以手动填写自己的命名如 xxx会议室、xxx 季度汇报等以供主控端识别
> 3：主控端先选择不同的客户端，选择后其余功能以及操作流程同当前版本

**交付形态**：单主控版（`../timer`）**一个字节不动**；新版本在 `../timer-multi/`，
独立数据目录、独立 exe、独立端口段。

## 二、逐条确认的 5 个决策

| # | 问题 | 用户选择 | 实现 |
|---|---|---|---|
| 1 | 一台客户端能否被多个主控控制 | **A 独占认领** | 客户端持 `claimed_by`；后来的主控收到 `busy` + 占用者名字 |
| 2 | 一个主控能否同时控多台 | **A 可以多选** | 表格多选，指令发给已选集合；客户端侧仍是严格一对一 |
| 3 | 客户端名称怎么填 | **运行即弹窗，默认电脑名** | `QInputDialog` 预填上次用过的名字（首次为电脑名） |
| 4 | 认领时客户端要不要确认 | **A 不确认** | 即刻生效，客户端弹托盘气泡 + 日志 |
| 5 | 主控崩溃/断网后怎么解锁 | **A 心跳超时自动释放** | 客户端 2s 心跳，15s 无应答自动解锁并广播 |

## 三、架构要点

1. **客户端连所有主控**（不是一个）
   这样每个主控都能看到全部客户端及其占用状态；否则"被小王占用"的机器在主控 A 的
   界面里会凭空消失，用户会以为那台机器不存在。

2. **占用由客户端裁决，主控只镜像**
   两个主控同时点认领 → 客户端先到先得，第二个回 `busy`。
   如果交给主控协商，就会出现"双主"（两边都以为自己成功了）。

3. **只有占用者的指令被执行**
   非占用者的 `START/PROMPT/CUSTOM/...` 一律回 `ACK{ok:false, reason:"not_owner"}` 并忽略，
   主控界面日志里写明「它正被『XXX』占用（请先认领）」。

4. **端口组支持同机多开**
   第 i 个主控用 UDP `47820+i*10` / TCP `47821+i*10`（最多 6 个）；客户端探测全部 6 组。
   主控端**取消单实例限制**（同机可开多个），客户端单实例限制保留。

5. **身份用 GUID，不用名字**
   客户端 `client_id` 首次生成后不变；主控 `master_id` 每进程一个。
   所以两台同名机器不会混，改名也不会丢认领关系。

6. **独立数据目录** `%LOCALAPPDATA%\MeetingTimerMulti`
   否则会和单主控版共用 `agenda.json` / 日志，互相覆盖。

## 四、协议扩展（帧格式不变，只加 type）

| 消息 | 方向 | 说明 |
|---|---|---|
| `CLAIM` / `CLAIM_RESULT` | M→C / C→M | 认领请求与结果（ok / busy / not_owner + owner） |
| `RELEASE` | M→C | 释放 |
| `CLAIM_STATE` | C→所有 M | 占用状态变化广播（让别人列表立刻变灰） |
| `REGISTER` / `HEARTBEAT` | C→M | 增加 `client_id`、`name`、`claimed_by` |
| `HERE` | M→C | 增加 `master_id`、`master_name`、`tcp_port` |

指令类消息类型**完全未变**，只是发送范围从"全部"变成"已选"，且客户端加归属校验。

## 八、v3.1 —— 修两个真 bug（都是实测报上来的）

### bug 1：客户端设置完名称十来秒后自己关了（托盘图标也消失）

**现象**：客户端启动 → 弹窗填名字 → 约 10 秒后进程消失，托盘图标一起没了。

**真因**：`TrayIcon.set_owner()` 里调了一个**不存在的方法** `_refresh_tooltip()`
（真实方法名是 `_refresh()`）。而 `set_owner` 是**被 Qt 信号调用的**
（`net.sigClaim -> tray.set_owner`），**PyQt5 里槽函数抛出未捕获异常会直接
`abort()` 整个进程** —— 不是"优雅退出"，是被杀掉，所以托盘图标瞬间消失。
触发条件：主控一认领这台客户端就必崩。

**修复**：改成 `self._refresh()`。
**回归**：`selftest_multi.py` 新增 `[10] 托盘集成` —— 直接调
`set_status` / `set_owner` / `set_countdown`，断言不抛异常。
这类 bug 纯协议测试是测不出来的（托盘根本没参与协议）。

### bug 2：主控界面里一台客户端都没有（客户端无限重连）

**现象**：客户端显示"已连接"，但主控列表是空的；客户端日志每 8 秒一条
「主控长时间无响应，断开重连」。

**真因**：主控收到 `HEARTBEAT` / `REGISTER` 后**不回 ACK**。
客户端靠"收到过数据"判断主控还活着（`last_rx`），而主控平时不主动发任何东西，
于是 8 秒后客户端认定主控已死 → 断开 → 重连 → 循环，主控列表永远是空的。

**修复**：主控对 `HEARTBEAT` 和 `REGISTER` 各回一个 `ACK`。

> ⚠️ **兼容性**：这个修复改的是**主控**。旧版主控 exe 不回心跳 ACK，
> 所以**新版客户端 + 旧版主控**仍会反复重连。**两个 exe 必须一起更新。**

## 九、v3.2 —— 修「多台客户端只显示最后一行」

**现象**（用户实测 + 截图）：同机开 3 个客户端，主控显示「在线客户端：3 台」，
但表格只有**最后一行**有内容，前两行只剩一个空勾选框。

**真因**：主控用 `client_id` 当表格行的键。
同机多开的客户端共用同一份 `client_config.json` → **三个进程的 client_id 完全相同**
→ 行键重复 → 后写的覆盖先写的，最后只剩一行有数据。

> 这不只是"测试才会遇到"：**把客户端目录整份复制到另一台机器**，同样会造成
> client_id 重复，主控会把两台真实机器显示成一台。

**修复**：
1. 主控注册表改成用**连接唯一键** `client_id@ip:端口`（`_by_key`），认领/下发/
   勾选/目标集合全部按这个键走。同名同 ID 的多台会各自成行。
2. 检测到同一 client_id 出现在两条连接上时，日志告警，并在**名字后面自动加
   连接端口**（`Q3季度会议（50069）`），否则两行名字一模一样分不清。
3. 顺带修了**客户端单实例锁没生效**：原来是 `removeServer()` 再 `listen()`，
   `removeServer` 会把正在运行的那个实例的锁删掉，所以能开出第 2、3 个。
   改成"先 `connectToServer` 探测，连得上就退出"。
4. 新增开关 `MEETINGTIMER_ALLOW_MULTI_CLIENT=1`：故意允许同机多开（测试用），
   此时每个实例带进程号作为会话 ID，主控能把它们当成不同机器分别认领。

**回归**（`selftest_multi.py` 新增 `[11]`，共 33 项）：

```

[PASS] 两台的连接键不同（不会互相覆盖）
[PASS] 两台的显示名被自动区分开（带端口后缀）
[PASS] 能单独认领其中一台
[PASS] 另一台没有被连带认领
```

## 十一、v3.4 —— 修「主控启动几次就多出几行客户端」

**现象**（用户实测）：只开 1 个客户端，主控反复启动 3 次，列表里出现 3 台同名客户端
（`Q3季度会议（57242）` / `（57243）` / `（57244）`，括号里是客户端的源端口）。

**真因**：主控每次启动都会生成**新的 `master_id`**，但**监听端口不变**（端口组会复用）。
于是客户端出现两条指向同一台主控的连接：

1. 重启前那条"老连接"按 `ip:端口` 自动重连 —— 实际连上的是**新主控**（但它以为还是老主控）；
2. UDP 发现又为新 `master_id` 建了一条新连接。

两条都发 REGISTER，主控按连接唯一键各记一行 → 同一台客户端显示 N 行，N = 主控启动次数。

**修复（三层）**：

1. **受理即自报身份**：主控接受连接后立刻发 `HELLO{master_id, master_name}`。
2. **客户端确认身份后才注册**：拿到 HELLO 比对；若和老连接的身份不符，就把它纠正成新身份；
   若已有另一条连接占着新身份，则**关掉这条遗留连接**（不再注册）。
   等不到 HELLO 时 2 秒后按老流程注册（兼容旧主控）。
3. **主控清理僵尸连接**：客户端被强杀/断网时 TCP 未必立刻报错，超过 20 秒没心跳就移除。

**顺带修掉一个隐蔽 bug**：客户端 socket 的信号原本用 `lambda lid=master_id` 绑定了 id，
一旦 `_adopt_master_id` 改了 `link.master_id`，后续所有信号都查不到这条连接 →
数据全丢 → 表现为"身份同步"后 8 秒又"长时间无响应"。已改成**绑定连接对象**。

**回归**（`selftest_multi.py` 新增 `[12]`，共 39 项）：

```
[PASS] 重启前：列表里 1 台
[PASS] 重启后端口与原主控相同（确实是端口复用场景）
[PASS] 重启后仍然只显示 1 台
[PASS] 重启后全程（含瞬间）都没有重复行   采样期间最大行数 = 1
[PASS] 第二次重启后还是 1 台（不会累积）
[PASS] 再过 6 秒也没有额外重复
```

**真机复验**（1 客户端 + 连续启动主控 3 次）：每轮 `连接 1 / 注册 1 / 重复告警 0`。
