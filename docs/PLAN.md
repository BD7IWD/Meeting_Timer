# 多主控 / 多客户端版本 —— 设计说明（v3.0）

> 作者：野怼怼；https://www.bd7iwd.com
>
> 本工程由单主控版本（`../timer`）派生。**原版本保持原样不动的交付态**，
> 本目录是独立产品，端口/配置/署名都自成一套。

---

## 一、需求确认（已逐条与你确认）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 一台客户端能否被多个主控控制 | **不能**。主控「认领」后独占；其他主控看到「已被 XXX 占用」，点不动 |
| 2 | 一个主控能否同时控多台 | **能**。多选，指令发给所有已选客户端（客户端侧仍是严格一对一） |
| 3 | 客户端名称怎么填 | **启动即弹窗要求填写**，默认预填「上次用过的名字」，首次为电脑名 |
| 4 | 认领时客户端是否弹窗确认 | **不确认**，即刻生效，客户端弹托盘气泡告知 |
| 5 | 主控崩溃/断网后怎么解锁 | **心跳超时自动释放**（15 秒收不到主控应答 → 自动解锁） |

配置默认：改名可在托盘菜单「设置本机名称」（不用重启）。

## 二、总体架构

```
        ┌──────────────┐            ┌──────────────┐
        │ 主控 A       │            │ 主控 B       │
        │ 认领：301、302│            │ 认领：401    │
        └──────┬───────┘            └──────┬───────┘
               │ TCP                          │ TCP
       ┌───────┴────────┬──────────┬──────────┴────────┐
       │                │          │                    │
 ┌─────▼─────┐   ┌──────▼────┐  ┌──▼──────┐   ┌────────▼───┐
 │ 301会议室 │   │ 302会议室 │  │ 401 汇报│   │ 402 空闲    │
 │ 占用:A    │   │ 占用:A    │  │ 占用:B  │   │ 占用:无     │
 └───────────┘   └───────────┘  └─────────┘   └────────────┘
```

**关键点**：每台客户端与**所有**发现到的主控都保持一条 TCP 连接（这样每个主控都能看到全部客户端
及其占用状态），但**只有占用者能下发指令**。非占用者的指令会被客户端拒绝并回 `not_owner`。

为什么不让客户端只连一个主控：那样主控 A 的列表里根本看不到"401 已被 B 占用"，
用户会以为那台机器不存在，体验很差。

## 三、身份与配置

| 项 | 说明 | 存放 |
|---|---|---|
| `client_id` | 客户端首次运行生成的 GUID，**稳定不变**。主控认客户端靠它，不靠名字 | `client_config.json` |
| `name` | 用户填的名字（301会议室 / Q3季度汇报）。改了不影响认领关系 | `client_config.json` |
| `master_id` | 主控**每个进程**一个 GUID（同机多开时互不混淆） | 内存 |
| `master_name` | 主控显示名，默认「电脑名 主控」，可在主控界面改 | `master_config.json` |

> 名字只用于显示。即使两台都叫「301会议室」，也因为 `client_id` 不同而不会混。

## 四、端口：同机多开的解决办法

原来固定 UDP 47820 / TCP 47821，一台机器只能开一个主控。新版本改成**端口组**：

| 主控实例 | UDP 发现 | TCP 控制 |
|---|---|---|
| 第 1 个 | 47820 | 47821 |
| 第 2 个 | 47821+10 = 47830 | 47831 |
| 第 i 个 | 47820 + i*10 | 47821 + i*10 |

- 主控启动时从 i=0 开始探测，找到第一个能绑定的组就用它（最多 6 个）。
- 客户端广播发现时**挨个探测这 6 个 UDP 端口**，把所有应答都收下来。
- 环境变量 `MEETINGTIMER_PORT_BASE` 可整体平移（默认 47820），用于避让别的程序。

## 五、协议扩展（在现有 JSON 帧上增加消息类型）

现有帧格式（magic + len + JSON + CRC32）**完全不动**，只增加 `type`。

| 消息 | 方向 | 载荷 | 说明 |
|---|---|---|---|
| `DISCOVER` | 客户端 → 广播 | `{}` | 探测主控（探测 6 个端口） |
| `HERE` | 主控 → 客户端 | `master_id, master_name, tcp_port` | 应答发现 |
| `REGISTER` | 客户端 → 主控 | `client_id, name, ip, mac, claimed_by` | 注册（连上就发） |
| `CLAIM` | 主控 → 客户端 | `master_id, master_name` | 认领 |
| `CLAIM_RESULT` | 客户端 → 主控 | `ok, reason, owner` | 认领结果 |
| `RELEASE` | 主控 → 客户端 | `master_id` | 释放 |
| `CLAIM_STATE` | 客户端 → 所有主控 | `claimed_by` | 占用状态变化广播（让别人的列表立刻变灰） |
| `HEARTBEAT` / `ACK` | 双向 | 现有机制 | 客户端 2 秒一次；**15 秒无应答 → 自动释放** |

指令类消息（`START / ADD_TIME / STOP / RESET / PROMPT / CUSTOM`）**类型不变**，
只是发送范围从"所有客户端"变成"已选中的客户端"，并且客户端会校验发送者是否为占用者。

## 六、客户端改动

| 项 | 改动 |
|---|---|
| 启动弹窗 | `QInputDialog` 预填「上次用过的名字」（首次电脑名），确认后保存并用于注册 |
| 托盘菜单 | 新增「设置本机名称」，随时可改，改完立刻重新注册（名字实时同步给所有主控） |
| 托盘悬停/状态弹窗 | 增加一行「当前控制：XXX 主控」或「空闲（未被认领）」 |
| 网络层 | 从"单主控连接"改成"多主控连接集合"，每条连接独立心跳/重连 |
| 指令校验 | 只接受占用者的指令；非占用者回 `not_owner` 并忽略 |
| 占用失效 | 占用者心跳超时 15 秒 → 自动清空占用并广播 `CLAIM_STATE` |
| 横幅/倒计时 | **完全不动**（继续沿用单主控版本的实现） |

## 七、主控端改动

客户端表格升级为「可认领列表」（在原表格上加两列，主界面布局基本不变）：

```
┌──────────────────────────────────────────────────────────────┐
│ 在线客户端：4 台       已选 2 台（301会议室、302会议室）        │
├────┬────────────┬──────────────┬────────────┬──────────┬──────┤
│ ☑  │ 名称        │ IP           │ 状态       │ 占用者   │ 剩余 │
├────┼────────────┼──────────────┼────────────┼──────────┼──────┤
│ ☑  │ 301会议室   │ 192.168.0.31 │ 已认领     │ 我       │ 25:00│
│ ☑  │ 302会议室   │ 192.168.0.32 │ 已认领     │ 我       │ 25:00│
│ ☐  │ 401 季度汇报│ 192.168.0.41 │ 已被占用   │ 小王主控 │  --  │
│ ☐  │ 402 待命    │ 192.168.0.42 │ 空闲       │ --       │  --  │
└────┴────────────┴──────────────┴────────────┴──────────┴──────┘
```

- **勾选 = 认领**（立即生效）；**取消勾选 = 释放**。不额外加"认领"按钮，少一次点击。
- 已被别人占用的行**灰显 + 勾选框禁用**，鼠标悬停提示「已被 小王主控 占用」。
- 标题行实时显示「已选 N 台」及名字，避免误发给不该发的机器。
- **没选任何客户端时**，开始/加时/提示/停止等按钮全部禁用，状态行提示「请先勾选要控制的客户端」。
- 其余（手动模式 / 会议议程 / 手动提示 / 自定义提示 / 节点设置）**操作流程与单主控版本完全一致**，
  只是目标集合从"全部"变成"已选"。

## 八、测试计划

新增 `tests/selftest_multi.py`，**同一台机器上跑 2 主控 + 2 客户端**（靠端口组隔离）：

1. 端口组：两个主控各占一组，互不冲突
2. 发现：每个客户端都能被两个主控看到，名字正确
3. 认领独占：M1 认领 C1 成功；M2 再认领 C1 → 失败且带占用者信息
4. 指令路由：M1 下发 → 只有 C1 收到；C2 收不到
5. 越权拒绝：M2 直接给 C1 发 START → 被拒（`not_owner`），C1 状态不变
6. 释放：M1 释放 C1 → M2 立刻能认领
7. 心跳超时：断开 M1 的连接 → 15 秒内 C1 自动解锁并广播
8. 改名：C1 改名 → 两个主控的列表都实时更新，认领关系不丢
9. 议程：两个主控各自的议程互不干扰，且只发给自己的已选客户端
10. 布局：会话/客户端表格排版回归（沿用 `layout_check.py` 思路）

另外保留原有的横幅几何/穿透/自动消失回归脚本。

## 十、与原版本的差异总览

| 维度 | 单主控版（../timer） | 本版（timer-multi） |
|---|---|---|
| 主控数量 | 1 | 最多 6（同机/跨机皆可） |
| 客户端归属 | 无概念，全部广播 | 独占认领，一对一 |
| 下发范围 | 全部客户端 | 已勾选的客户端 |
| 客户端身份 | 电脑名 | 用户填写的名字（GUID 保证唯一） |
| 客户端启动 | 静默进托盘 | 先弹窗填名称 |
| 崩溃恢复 | 不涉及 | 心跳超时自动释放 |
| 端口 | 固定 47820/47821 | 端口组，支持同机多开 |
